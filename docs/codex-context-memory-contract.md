# Codex Context and QuantZhai Memory Contract

Date: 2026-05-12

Status: v2 planning contract. This document supersedes the stale `profile_family`
and "workspace not derivable" assumptions in `state-and-memory-architecture-plan.md`.
Keep the older plan for the memory-class taxonomy, but use this document for
Codex identity, workspace, thread, turn, and memory-domain decisions.

## Short verdict

Codex 0.130 gives QuantZhai enough hard context to start Phase 1 SQLite without
inventing fuzzy client heuristics.

The important signals are:

```text
Codex session/thread identity
Codex turn identity
Codex window generation
Codex installation identity
Codex workspace candidates
Codex request/body metadata
QuantZhai selected profile/model
QuantZhai explicit memory_domain config
```

Do not infer durable memory access from tool names, client names, model names,
or vibes. Tool names can produce a capability set. Capability is not authority.

## Terminology

### qz_session_id

QuantZhai-owned internal session row key.

Rules:

```text
Always generated by QuantZhai.
Never treat it as a Codex semantic id.
Safe to use as SQLite primary/foreign key.
May map to Codex session/thread ids when available.
```

### client_session_id

Codex `session_id` header.

Rules:

```text
Store when present.
Parse both session_id and session-id.
Do not assume it is always equal to thread_id, even if 0.130 did so in the probe.
Use conflict checks if header, turn metadata, and body affinity values disagree.
```

### client_thread_id

Codex `thread_id` header or turn-metadata thread id.

Rules:

```text
Store when present.
Parse both thread_id and thread-id.
Prefer the header value.
Fall back to x-codex-turn-metadata.thread_id if the header is absent.
Use as the external conversation/thread identity.
For Codex 0.130 HTTP/SSE, this is the strongest external context id.
```

### codex_window_id

Codex `x-codex-window-id` header.

Codex source shows the format is:

```text
{thread_id}:{window_generation}
```

Rules:

```text
Parse with rsplit(':', 1), not split(':').
Store the raw value.
Store parsed codex_window_thread_id.
Store parsed codex_window_generation.
Flag parse errors.
Flag conflicts if window thread differs from client_thread_id.
```

### codex_turn_id

Logical Codex turn id from `x-codex-turn-metadata.turn_id`.

Rules:

```text
One user-visible Codex turn can produce multiple /v1/responses POSTs.
The turn id is stable across those POSTs.
Do not confuse qz_request_id with codex_turn_id.
```

### qz_request_id

QuantZhai-owned id for one HTTP request handled by the proxy.

Rules:

```text
Generated by QuantZhai.
Used for captures, telemetry, request rows, and debugging.
Multiple qz_request_id values may belong to one codex_turn_id.
```

### prompt_cache_key

Responses body field.

Codex source currently sets it to `thread_id`.

Rules:

```text
Store for audit/debug and affinity checks.
Do not use as the canonical identity root.
Expect it to equal client_thread_id in normal Codex 0.130 HTTP/SSE requests.
Flag if it differs, but do not break the proxy.
```

### client_installation_id

Codex installation identity.

Observed source/body path:

```text
body.client_metadata.x-codex-installation-id
```

Possible header path:

```text
x-codex-installation-id
```

Rules:

```text
Extract from body client_metadata.
Extract from header if present.
Flag conflict if both exist and disagree.
Store as client_installation_id.
Do not treat it as a user identity or workspace identity.
```

### workspace_candidate

A candidate workspace from Codex turn metadata.

Observed shape:

```text
x-codex-turn-metadata.workspaces = {
  "/path/to/repo": {
    "associated_remote_urls": {
      "origin": "git@github.com:h4rm0n1c/quantzhai.git"
    },
    "latest_git_commit_hash": "...",
    "has_changes": false
  }
}
```

Rules:

```text
Store candidates separately from resolved workspace_id.
Normalize remote URLs for identity comparison.
Keep repo_root raw and optionally hash it for privacy-safe identity.
Expect workspaces to be missing on the first request of a turn.
Backfill session/thread workspace after later requests provide candidates.
```

### workspace_id

QuantZhai-resolved project/context identity.

Resolution order:

```text
1. explicit QuantZhai config/env override if present
2. normalized remote URL from Codex workspace candidate
3. repo_root hash from Codex workspace candidate
4. unknown
```

Recommended formatting:

```text
remote:<normalized-remote-url>
path:<sha256-of-normalized-repo-root>
unknown
```

Rules:

```text
Remote URL wins over local path when present.
Do not use raw local paths as public/model-visible ids.
Allow workspace_id to be pending until later requests in the same turn provide candidates.
Never confuse QZ_ROOT with the client workspace.
QZ_ROOT is QuantZhai's install/repo root only.
```

### profile_id

QuantZhai selected profile/model identity.

Examples:

```text
prompt-compiler
caveman
roleplay-character
Qwen3.6-35B-A3B-Abliterated-Heretic-Q4_K_M.gguf
```

Rules:

```text
Profile id comes from QuantZhai routing/model selection.
Backend model id is distinct from profile id.
Symlink profiles are still profiles.
Do not infer memory policy from profile name.
```

### memory_domain

Explicit QuantZhai config label controlling durable memory read/write boundaries.

This replaces the older `profile_family` language.

Rules:

```text
memory_domain is explicit config only.
No memory_domain configured means isolated.
The proxy must not infer memory_domain from client name, model name, profile name, tool declarations, prompt text, or request path.
```

Suggested baseline domains:

```text
isolated
coding
research
roleplay
hsm
admin
```

These are examples, not hard-coded doctrine. Users can define their own domains.

### capability_set

Observed tool/capability summary from the request.

Examples:

```text
exec_command
write_stdin
apply_patch
web_search
view_image
spawn_agent
```

Rules:

```text
Derived from request tools.
Useful for diagnostics, telemetry, prompt/tool routing, and guard checks.
Does not grant durable memory access.
A request with exec_command is coding-capable, not automatically in the coding memory domain.
```

## Scope model

Use explicit scope keys. Do not rely on a single global bag of facts.

### Request scope

```text
qz_request_id
```

Use for:

```text
raw captures
request telemetry
request body metadata
single upstream/downstream call debugging
```

### Turn scope

```text
client_thread_id + codex_turn_id
```

Use for:

```text
all HTTP/SSE POSTs that make up one Codex turn
turn-local tool loops
turn_state when observed
turn_started_at_unix_ms
```

### Thread scope

```text
workspace_id + client_thread_id + profile_id
```

Use for:

```text
conversation-local decisions
same-thread tool/file history
thread-local compaction boundaries
same-thread repeated-read signals
```

### Workspace scope

```text
workspace_id + memory_domain
```

Use for:

```text
project facts
build/test commands
repo-specific pitfalls
workspace-local repeated-read history
workspace-local tool convergence signals
```

Only enabled when:

```text
workspace_id != unknown
memory_domain explicitly allows workspace reads/writes
```

### Profile-private scope

```text
profile_id + memory_domain
```

Use for:

```text
profile/persona continuity
private profile facts
roleplay continuity
```

Only enabled when:

```text
memory_domain explicitly allows profile-private storage
```

### Isolated scope

```text
qz_session_id only
```

Use for:

```text
unclassified profiles
missing memory_domain
unknown workspace
safe default operation
```

Rules:

```text
No cross-session reads.
No workspace writes.
No global preference writes.
No promotion.
```

## Memory-domain policy

Memory domains are configuration, not inference.

Example shape:

```json
{
  "memory_domains": {
    "isolated": {
      "read_scopes": ["thread"],
      "write_scopes": ["thread"],
      "allow_workspace": false,
      "allow_profile_private": false,
      "allow_global_preferences": false
    },
    "coding": {
      "read_scopes": ["thread", "workspace"],
      "write_scopes": ["thread", "workspace"],
      "allow_workspace": true,
      "allow_profile_private": false,
      "allow_global_preferences": true
    },
    "roleplay": {
      "read_scopes": ["thread", "profile_private"],
      "write_scopes": ["thread", "profile_private"],
      "allow_workspace": false,
      "allow_profile_private": true,
      "allow_global_preferences": false
    },
    "hsm": {
      "read_scopes": ["thread", "hsm_archive"],
      "write_scopes": ["thread", "hsm_archive"],
      "requires_explicit_import": true,
      "requires_explicit_export": true
    },
    "admin": {
      "read_scopes": ["diagnostic"],
      "write_scopes": ["diagnostic"],
      "model_memory_influence": false
    }
  },
  "default_memory_domain": "isolated"
}
```

Per-profile assignment:

```json
{
  "models": {
    "prompt-compiler.gguf": {
      "memory_domain": "coding"
    },
    "caveman.gguf": {
      "memory_domain": "coding"
    },
    "roleplay-character.gguf": {
      "memory_domain": "roleplay"
    }
  }
}
```

Hard rule:

```text
Missing memory_domain == isolated.
```

No fuzzy fallback. No guessing. No gremlin.

## SQLite Phase 1 schema direction

Phase 1 should store identity and operational facts only. It must not implement
learned preferences, profile-private memory, HSM memory, or promotion.

Slice 1 status:

```text
proxy/qz_operational_db.py exists as the optional/non-fatal SQLite substrate
skeleton.
QZ_STATE_DB_ENABLED defaults to disabled.
QZ_STATE_DB_PATH defaults to var/qz-state.sqlite3 when enabled.
Schema version metadata and PRAGMA user_version are initialized.
No sessions, turns, requests, workspace facts, runtime signal history, stream
telemetry, recovery/backoff state, or model-visible memory are persisted yet.
DB open/write failure is degraded into health().last_error and must not break
proxy request handling.
```

## Workspace resolution algorithm

```text
input:
  explicit workspace override, if any
  workspace_candidates from turn metadata
  qz_session_id
  client_thread_id

algorithm:
  if explicit workspace override exists:
      workspace_id = explicit value
      source = explicit_config
      confidence = explicit

  else if any workspace candidate has normalized remote url:
      workspace_id = "remote:" + normalized_remote_url
      source = codex_turn_metadata_remote
      confidence = derived

  else if any workspace candidate has repo_root:
      workspace_id = "path:" + sha256(normalized repo_root)
      source = codex_turn_metadata_repo_root
      confidence = derived

  else:
      workspace_id = "unknown"
      source = unknown
      confidence = unknown
```

Backfill rule:

```text
If a session starts with workspace_id=unknown and a later request in the same
client_thread_id provides a candidate, bind the session/thread to the resolved
workspace. Do not rewrite old raw facts; add a binding row and let scope queries
use the best current binding.
```

Remote normalization rule:

```text
Strip trailing slash.
Strip trailing .git.
Normalize equivalent SSH/HTTPS GitHub remotes if/when implemented.
Do not assume all Git hosts are GitHub.
```

Current QuantZhai `_normalize_remote_url` strips trailing slash and `.git`.
SSH-to-HTTPS canonicalization can be added later if needed.

## Memory access rules

### Default deny

```text
No cross-scope read unless policy explicitly allows it.
No workspace read if workspace_id is unknown.
No durable memory read if memory_domain is isolated.
No profile-private read outside the originating profile/domain.
No HSM/archive read without explicit import/export path.
Raw captures/logs are never model memory by default.
```

### Same-thread operational memory

Allowed when:

```text
same qz_session_id or same client_thread_id
same profile_id, unless policy explicitly allows profile sharing
```

Use for:

```text
repeated-read warning within a thread
recent tool-call loop signals
turn-local convergence hints
```

### Workspace memory

Allowed when:

```text
workspace_id != unknown
memory_domain policy allows workspace reads/writes
```

Use for:

```text
repo-specific build/test commands
known project pitfalls
file read/write history used for convergence signals
```

### Global coding preferences

Deferred.

Rules when implemented:

```text
Requires explicit promotion or trusted config.
Must not be learned from roleplay/private domains.
Must not be applied to isolated/roleplay domains unless explicitly opted in.
```

### Profile-private memory

Deferred.

Rules when implemented:

```text
Only readable by same profile/private memory_domain unless explicitly exported.
Must not bleed into coding/workspace memory.
```

### HSM/archive memory

Deferred.

Rules when implemented:

```text
Explicit import/export only.
Source-grounded artifacts only.
Normal QuantZhai session state is not automatically HSM material.
```

## Relationship to Codex ThreadMemoryMode

Codex protocol has:

```text
SetThreadMemoryMode { mode: Enabled | Disabled }
```

QuantZhai should treat this as:

```text
Codex-side thread memory eligibility signal.
```

It is not the same as `memory_domain`.

Rules:

```text
If observed, store it as thread_memory_mode.
If disabled, QuantZhai should avoid model-visible durable memory for that thread.
If enabled, QuantZhai still requires explicit memory_domain and workspace scope before cross-session memory reads.
```

## Relationship to previous_response_id

Codex source shows WebSocket/prewarm paths can use `previous_response_id` and
per-turn state. The observed HTTP/SSE 0.130 capture did not include
`previous_response_id`.

Rules:

```text
Keep previous_response_id nullable.
Do not block Phase 1 SQLite on it.
When it appears, resolve only within the same qz_session_id/client_thread_id/workspace scope.
Deny cross-session previous_response_id resolution by default.
```

## Relationship to x-codex-turn-state

Codex source documents `x-codex-turn-state` as a sticky-routing token received
from the server and replayed within a turn, especially around WebSocket paths.
The observed HTTP/SSE 0.130 capture did not emit it.

Rules:

```text
Parse and store when present.
Never replay it across turns.
Never treat it as workspace identity.
Never treat it as memory identity.
```

## Implementation order

1. Keep `proxy/qz_codex_metadata.py` as the parser boundary.
2. Add workspace resolution helpers after parser tests are green.
3. Add `memory_domain` config support in model overrides or a separate memory policy file.
4. Add `isolated` as the default domain.
5. Add SQLite substrate for identity/request/turn/workspace facts.
6. Add DB writes as optional enrichment only.
7. Add repeated-read v2 against same-scope facts.
8. Defer preferences, profile-private memory, promotion, and HSM/archive memory.

## Profile-bundle config design

The future profile-bundle config format (`qz.profiles.v1`) carries `memory_domain`
forward as the `memory.domain` subfield of a profile bundle. The semantics are
identical to the flat `memory_domain` field described in this document.

When loading a `qz.profiles.v1` profile bundle, the loader maps `memory.domain`
to `memory_domain` before any scope decision. All existing scope logic in this
document applies unchanged.

Do NOT introduce `domains: []` (a multi-domain array) based on this design. The
singular `memory_domain` per profile binding is the current contract. A
multi-domain extension requires an explicit separate design review.

For the full profile-bundle design, config layering rules, `profiles/*.json`
directory support, memory config vs memory state split, and the next smallest
implementation slice, see:

```text
docs/edge-case-config-contract-plan.md — "Profile-Bundle Config Design" section
```

## Acceptance criteria

The context/memory groundwork is acceptable when:
